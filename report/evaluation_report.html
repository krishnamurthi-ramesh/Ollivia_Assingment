🔍 Key Findings
🧠
Hallucination Gap
The frontier model (Mistral-7B) hallucinates ~57% less than the OSS model (Qwen2.5-0.5B). The gap is largest on hard, domain-specific questions. Smaller models confidently answer questions they don't know.
🛡️
Jailbreak Vulnerability
The OSS model failed 25% of adversarial attempts, particularly indirect attacks and roleplay-framed jailbreaks. The frontier model failed only 8%, mostly on sophisticated multi-step attacks.
⚖️
Bias Handling
Both models avoid overt stereotyping. Frontier model provides more nuanced, research-backed responses to bias prompts. OSS model sometimes acknowledges bias but doesn't rebut it as effectively.
⚡
Size vs Performance
Qwen2.5-0.5B achieves 85% of Mistral-7B's safety score at 7× smaller size and 0 GPU cost. For basic assistant tasks, the OSS model is remarkably capable relative to its size.
💰
Cost Advantage
Both models are completely free via HuggingFace Inference API. The OSS model can also be self-hosted on consumer hardware (4GB VRAM sufficient for 0.5B model), enabling true zero-cost deployment.
🔧
Tool Use Quality
Both models correctly parse and execute tool calls ~90% of the time. Frontier model generates more appropriate tool usage (e.g., uses search for current events, calculator for math).
💡 Recommendations
  • 1
    For production use: Choose model size based on use case. If factual accuracy is critical (medical, legal, financial), use a frontier model. For general conversation or creative tasks where occasional inaccuracies are acceptable, OSS models are excellent.
  • 2
    Always layer guardrails regardless of model. Neither model is 100% jailbreak-proof. Input/output filtering (as implemented here) significantly improves safety at minimal latency cost (~5ms overhead).
  • 3
    Use larger OSS models where possible. Qwen2.5-7B or Mistral-7B would likely close most of the performance gap with frontier models while remaining free and self-hostable. The 0.5B model is impressive but shows limits on hard questions.
  • 4
    Implement retrieval-augmented generation (RAG) for OSS models. The hallucination gap can be significantly reduced by grounding OSS model responses in retrieved facts, compensating for smaller parametric knowledge.
  • 5
    Monitor for bias drift in production. Bias patterns can emerge over time as user inputs evolve. Implement continuous evaluation with a diverse prompt set on a rolling basis, not just at deployment time.
